# tools/ — 人格 OS 的可执行装置

> 这个目录解决一个具体问题：`0_system/evolution_protocol.md` 写的六步闭环里，
> 第 3 环（输出）和第 4 环（反馈）没有强制机制，导致闭环实际不转。
>
> 这里放的脚本，把"AI 应当自动完成"变成"AI 执行命令"，把"我应当记得"变成"它拦着我"。

## 先看这个

**`LAUNCHER_启动器说明.md`** — 装完就不用再想了。想一次性搞清楚这套东西怎么跑，先读那份。

## 脚本

| 脚本 | 作用 | 什么时候跑 |
|------|------|-----------|
| `launcher.py` | 一键装 hook + 定时采集；也管状态查询和卸载 | 装一次，之后用 `status` |
| `capture.py` | 从 AI 客户端本地日志捞对话，生成待审草稿 | 每 2 小时自动（或手动） |
| `evolve.py` | 扫描沉淀目录，报告哪些还是空模板；维护状态文件 | 会话结束 + push 前 |
| `lint_output.py` | 检查一份输出是否符合 `quality_control.md` 可判定的部分 | 输出正文类内容后 |
| `install_hooks.py` | 单独装 git hook（launcher 会自动调用，一般不用单独跑） | — |

## 一句话装好

```bash
python tools/launcher.py install
```

## 设计原则

1. **只做 AI 判不了的事。** 风格、洞察、锐度不写进脚本——
   脚本判不了的东西硬判，只会训练出"为了过检而写作文"。
2. **优先拦截，而不是提醒。** 提醒执行了五个月一次没执行过；
   拦在 commit 上，它就没地方躲。
3. **状态写在仓库里。** `9_meta/evolution_state.json` 让"有没有在进化"变成可查的数字，
   不再依赖记忆和感觉。
4. **只读客户端数据。** `capture.py` 对 AI 客户端的日志只读，不写、不删、不改。
5. **不做它做不到的承诺。** 自动判断价值、编造决策内容——这两件都不做，
   原因写在 `LAUNCHER_启动器说明.md` 里。

## 已知限制

- **git hook 只在本地 clone 生效**，不随 git 同步。换机器要重装。
- **定时任务可能被系统策略拦截**（如 `schtasks`）。装不上时改手动跑，不影响质量。
- **WorkBuddy 的对话正文不在本地库**，采集器采不到。这是客户端的数据存放决定，
  不是脚本能解决的。

全部脚本都是纯标准库 Python 3，无第三方依赖。
