# 决策案例：这套系统唯一不可替代的东西

## 为什么要写这个

规则谁都能写。"要犀利""要有洞察""看人性"——这些话任何人都能说。
**决策轨迹只有做过的人才有。**

一个决策案例记录的是：
> 当时发生了什么 → 你看到了什么 → 你怎么判断 → 选了什么 → 实际结果如何 → 错了哪

AI 读完这些，能学到"遇到类似情况该怎么想"。
AI 读完一万条禁令，也学不到这个。

**这也是这套系统能不能长期进化的分水岭。**
没有决策案例，规则会越来越厚，判断不会越来越准。

## 写什么

三类，都算：

1. **接不接一个客户** — 业务判断，门槛最低，建议先写这类
2. **要不要涨价 / 改交付** — 商业判断
3. **内容上要不要换方向** — 内容判断

不需要多复杂。**一个真实的小决定，比十条正确的道理有用。**

## 怎么写

文件名：`YYYY-MM-DD_一句话概括.md`
放在本目录下。

### 模板（照填，删不掉的行留着就行）

```markdown
# 决策：<一句话，说清你做了什么决定>

**日期：** YYYY-MM-DD

## 情境
当时是什么情况。谁来找你、要什么、有什么约束条件。
（3-5 句，写具体。别写"一个客户"）

## 我看到的信号
让你产生判断的具体线索。不是结论，是线索。
- 线索一
- 线索二

## 我的判断
我认为真实情况是什么，为什么这么认为。

## 三个选项
| 选项 | 我的看法 |
|------|---------|
| A. | |
| B. | |
| C. | |

## 我选了
选哪个，理由是什么。

## 被否掉的方案 + 为什么否
这条最重要。否掉的方案说明了你的判断边界在哪。

## 预期结果
我当时以为会怎样。

## 实际结果
后来怎样。**这一栏必须填真实的，哪怕结果是"没结果"。**
留空等于没写。

## 教训
下次遇到类似情况，改什么。

## 可复用模式
一句话抽象出来，可写进 2_cognition/pattern_recognition.md
```

## 填空成本参考

最短可用的版本：**情境 3 句 + 判断 2 句 + 选了什么 + 实际结果 1 句**。
这样一篇 200 字就够。200 字 × 20 条 = 4000 字，比现在 0 字强一百倍。

## 反面例子

- ❌ "2026-05-10 决定做短视频" — 没有情境、没有被否方案、没有结果，等于没写
- ❌ "我认为应该重视用户" — 这是价值观，不是决策
- ❌ 编造一个看起来合理的案例 — 比空着更糟，会污染整个系统

**宁可写得糙、写得少，也不要写假的。**
`6_memory/failures/` 同理：失败的决策比成功的更值钱，因为它记录了判断边界。
