# inbox/ — 待审草稿区

## 这里放什么

`tools/capture.py` 从 AI 客户端本地日志捞到的对话，**未经过滤**，
自动生成为 `YYYY-MM-DD_来源_签名.md` 放在本目录。

## 怎么处理

每份草稿开头有同一个三问：

1. 里面有没有一个**真实的决策**（做了什么选择、被否了什么、结果如何）？
2. 有没有一条 **AI 说错了、你纠正了**的地方？
3. 有没有一个**当时以为对、后来被验证是错的**判断？

| 答案 | 动作 |
|------|------|
| 有一条"是" | 提炼进 `3_behavior/decision_cases/` 或 `7_ai_training/corrected_outputs/` 或 `6_memory/failures/`，然后删掉草稿 |
| 三条都是"否" | 直接删掉，不用留 |
| 不确定 | 删掉。判断不了价值 = 没有价值 |

## 为什么要多这一步

**自动提炼会把垃圾和金子一起捡进去。**

一份 200 轮的对话里，真正有决策价值的可能只有 3 句。
脚本能捞出 200 句，但挑不出那 3 句——那是上下文理解，只有读的人才知道。

所以 `capture.py` 故意只做搬运，不做判断。

## inbox 应该保持为空

草稿堆积 = 有人在偷懒不处理。
**inbox 里长期有文件，说明这套机制已经退化成垃圾场。**

判断标准：草稿产生后 1-2 天内必须清掉。

正常情况下这里应该是空的，或者只有 1-2 份刚生成的。

## 手动触发

```bash
python tools/capture.py --days 3 --draft
```

定时任务每 2 小时会自动跑一次。等不及就手动跑。
